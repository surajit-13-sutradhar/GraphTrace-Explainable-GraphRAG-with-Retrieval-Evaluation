# Checkout Service and Payment Service

## Checkout Service
The Checkout Service powers Subscription Checkout. It validates the selected plan, creates an order record in the Billing Database, and then calls the Payment Service to charge the customer.

## Identity handling
The Checkout Service trusts the identity headers added by the API Gateway and never calls the Auth Service directly.

## Payment Service
The Payment Service is the only component that talks to the external Payment Provider, PayFlow. It sends charge requests to PayFlow over HTTPS with a 10-second timeout and records each attempt in the Billing Database.

## Payment events
When PayFlow confirms a charge, the Payment Service publishes a payment.completed event to the Event Queue. If the charge is declined, it publishes payment.failed instead. The Billing Service consumes payment.completed events. The Notification Service consumes both event types.

## Idempotency
Every charge request includes an idempotency key generated by the Checkout Service, so retries never double charge a customer.

## Failure behavior
If PayFlow does not respond within the timeout, the Payment Service returns a pending status to the Checkout Service. The Checkout Service shows the customer a "payment processing" message and does not create a second charge. A reconciliation job in the Payment Service resolves pending payments every five minutes.
